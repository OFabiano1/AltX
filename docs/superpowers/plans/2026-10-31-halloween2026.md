# conquista halloween 2026 + daily do dia 31 — plano de implementação

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**goal:** no dia 31/10/2026 (UTC-3), o `>daily`/`/daily` dá pacote de halloween (50 extra de dima, 1 extra de ametista, 20 doces, numa única transação) e desbloqueia a conquista `halloween2026` ("halloween 2026"), visível no `>saldo`/`/saldo`.

**arquitetura:** base mínima de conquistas em `data.py` ( tabela `conquistas` volta ao schema, mesmo formato do antigo — ninguém tinha dados, `CREATE TABLE IF NOT EXISTS` não precisa migração). catálogo/display de halloween fica na cog `halloween`. a lógica de bônus e display fica na cog `economia`, que já é dona do `>daily`/`>saldo`.

**tech stack:** discord.py 2.x, sqlite (wal, transação atômica por operação), pytest.

**spec:** docs/superpowers/specs/2026-10-31-halloween2026-design.md (resumo combinado no chat: pacote completo só no dia 31; janela da conquista = só 31/10/2026).

## global constraints

- tudo em minúsculo nos arquivos; comentários com `# ─── nome ───` separando seções.
- embeds roxo (`visual.PRIMARY`); só os 3 customs do servidor (`visual.AXOLOTL`, `visual.AMETHYST`, `visual.DIAMANTE`) — unicode nunca.
- todo comando `>` tem gêmeo `/` com o mesmo nome.
- saldo nunca negativo (checar antes de debitar); operação econômica = transação atômica (`BEGIN IMMEDIATE` + `_lock`).
- schema só muda com `CREATE TABLE IF NOT EXISTS` idempotente — sem migração necessária aqui.
- números de display = quantias concedidas (constantes), não saldos totais da tabela.

## review focus

- **usuário com doces antes do daily:** no dia 31, o saldo final de doces = doces de farm + 20 — mensagem mostra o bônus concedido (20), não o total. teste `test_daily_doces_vao_juntas`.
- **borda de fuso:** 00:00–02:59 UTC de 01/11 ainda é 31/10 em br → vale bônus; 00:00–02:59 UTC de 31/10 ainda é 30/10 em br → não vale. teste `test_bonus_halloween_so_no_dia`.
- **resgate duplo:** quem já resgatou hoje nega e nada muda, nem doces, nem conquista. `test_daily_doces_vao_juntas` (2ª chamada).
- **conda resolvida 2x:** `dar_conquista` 2ª vez = False, display continua uma linha só. `test_conquista_uma_vez`.
- **import cruzado de cog:** `economia` importa `from cogs.halloween import linha_conquista` — módulo nível-raiz não pode tocar no bot. `test_ajuda` (carrega todas as cogs) cobre.

```python
def test_bonus_halloween_so_no_dia():
    from datetime import datetime, timezone

    from cogs.economia import bonus_hoje

    # 09h de 31/10 em br.
    a = datetime(2026, 10, 31, 12, 0, tzinfo=timezone.utc)
    assert bonus_hoje(a) == (50, 1, 20)
    # 22h de 31/10 em br = 01h utc de 01/11: ainda vale.
    b = datetime(2026, 11, 1, 1, 0, tzinfo=timezone.utc)
    assert bonus_hoje(b) == (50, 1, 20)
    # 00h de 01/11 em br = 03h utc: acabou.
    c = datetime(2026, 11, 1, 3, 0, tzinfo=timezone.utc)
    assert bonus_hoje(c) == (0, 0, 0)
    # 21h de 30/10 em br estar em utc 31 de 30T00:00: ainda não.
    d = datetime(2026, 10, 31, 0, 0, tzinfo=timezone.utc)
    assert bonus_hoje(d) == (0, 0, 0)
```
